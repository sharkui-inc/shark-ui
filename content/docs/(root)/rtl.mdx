## Overview

Shark components ship RTL-ready. This page covers enabling and testing direction.

RTL flips reading order, alignment, and some controls. It does not mirror every icon or layout.

## Set the document direction

If you know the locale when the document renders, set `lang` and `dir` on `<html>`. `lang` names the language; it does not choose text direction for you.

Common RTL locales include `ar-SA`, `ar-BH`, `he-IL`, and `fa-IR`. Without `LocaleProvider`, the default is `en-US` and `ltr`.

## Change direction in a client subtree

For a client-side locale switcher, put `dir` and `lang` on the localized subtree. Do not render `<html>` from an application component.

```tsx title="settings-panel.tsx"
"use client";

import React from "react";
import { LocaleProvider, useLocale } from "@/components/ui/locale";

const LocalizedContent = (props: { children: React.ReactNode }) => {
  const { locale, dir } = useLocale();

  return (
    <section dir={dir} lang={locale}>
      {props.children}
    </section>
  );
};

export const SettingsPanel = (props: { children: React.ReactNode }) => {
  const [locale, setLocale] = React.useState("ar-SA");

  return (
    <LocaleProvider locale={locale}>
      <select onChange={(event) => setLocale(event.target.value)} value={locale}>
        <option value="en-US">English</option>
        <option value="ar-SA">Arabic</option>
        <option value="he-IL">Hebrew</option>
      </select>
      <LocalizedContent>{props.children}</LocalizedContent>
    </LocaleProvider>
  );
};
```

`LocaleProvider` holds the active locale. `useLocale` returns `locale` and `dir`.

## Use logical properties

Prefer utilities that follow reading order instead of physical left and right.

| Avoid | Use instead |
| --- | --- |
| `text-left`, `text-right` | `text-start`, `text-end` |
| `ml-*`, `mr-*` | `ms-*`, `me-*` |
| `pl-*`, `pr-*` | `ps-*`, `pe-*` |
| `left-*`, `right-*` | `start-*`, `end-*`, `inset-s-*`, `inset-e-*` |
| `border-left-*`, `border-right-*` | `border-s-*`, `border-e-*` |
| `rounded-l-*`, `rounded-r-*` | `rounded-s-*`, `rounded-e-*` |
| `slide-in-from-left/right` | `slide-in-from-start/end` |

If a centered element still needs a horizontal transform that depends on the inline axis, add an `rtl:` translation variant beside the logical placement.

## What to mirror

Mirror controls that track reading order or horizontal movement:

- Back and forward navigation
- Steppers and directional arrows
- Reading-progress fills and illustrated sequences

Keep these physical:

- Media playback controls, clocks, and circular progress
- Checkmarks, numbers, URLs, code, charts, and graphs
- Image cropper handles and other visual coordinates
- Images that need a separate RTL asset when direction matters

## Format dates, translate copy separately

`useDateFormatter` localizes dates and numbers. It does not translate labels or messages.

```tsx
import { useDateFormatter } from "@/components/ui/locale";

const LaunchDate = () => {
  const formatter = useDateFormatter({
    dateStyle: "long",
    timeZone: "UTC",
  });

  const date = new Date("2026-03-15T00:00:00Z");

  return <time dateTime="2026-03-15">{formatter.format(date)}</time>;
};
```

## Test overlays and inputs

Check components in the open state:

- Open `Dialog`, `Menu`, `Popover`, and `Select`. Verify placement, focus order, and Escape.
- Exercise `Date Input`, `Date Picker`, ranges, and clear controls in both directions.
- Confirm directional icons, keyboard navigation, and horizontal control order.

## RTL review checklist

- Switch between an LTR and RTL locale at desktop and narrow widths.
- Scan alignment, padding, borders, and transforms for leftover physical `left`/`right` values.
- Open overlays and walk Tab, arrow keys, and Escape.
- Check dates, ranges, emails, URLs, IDs, and mixed RTL and Latin text.
