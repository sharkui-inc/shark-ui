## Usage

```tsx
import {
  NavigationMenu,
  NavigationMenuContent,
  NavigationMenuItem,
  NavigationMenuLink,
  NavigationMenuList,
  NavigationMenuTrigger,
} from "@/components/ui/navigation-menu";
```

```tsx
<NavigationMenu aria-label="Main navigation">
  <NavigationMenuList>
    <NavigationMenuItem value="components">
      <NavigationMenuTrigger>Components</NavigationMenuTrigger>
      <NavigationMenuContent>
        <NavigationMenuLink href="/docs/components/button">Button</NavigationMenuLink>
        <NavigationMenuLink href="/docs/components/menu">Menu</NavigationMenuLink>
      </NavigationMenuContent>
    </NavigationMenuItem>
    <NavigationMenuItem value="docs">
      <NavigationMenuLink href="/docs">Documentation</NavigationMenuLink>
    </NavigationMenuItem>
  </NavigationMenuList>
</NavigationMenu>
```

Triggers and links support `asChild` with one child. Chevrons are explicit children in the examples, so the trigger can also merge onto your own button.

### Shared viewport

Keep content inside its item and add one viewport after the list. Ark moves the active content into it and measures its dimensions. Do not add another Portal or render the content a second time inside the viewport.

Set `lazyMount={false}` and `unmountOnExit={false}` on the root when using a shared viewport. Ark detects the viewport during initial mounting, so it must remain in the DOM while closed. This example overrides the Shark defaults for that composition.

## Viewport size

The following CSS variables are exposed on `NavigationMenu` and `NavigationMenuViewport`:

| Variable | Description |
| --- | --- |
| `--trigger-width`, `--trigger-height` | Active trigger dimensions. |
| `--trigger-x`, `--trigger-y` | Active trigger coordinates used by the shared indicator. |
| `--viewport-width`, `--viewport-height` | Active content dimensions used by the viewport. |
| `--viewport-x`, `--viewport-y` | Viewport coordinates calculated by Ark. |

Use `--viewport-width` and `--viewport-height` to size the shared panel. Shark already applies those variables and a 200 ms width/height transition on `NavigationMenuViewport`.

Standalone panels own their border and shadow. Inside a shared viewport, the viewport owns that surface instead. Reduced motion disables animations and transitions.

## Accessibility

Give the navigation an accessible name with `aria-label`. Triggers expose expanded state and links support `aria-current`. Tab follows the focusable content. Vertical navigation and RTL use Ark's direction-aware keyboard behavior.

Complies with the [Navigation Menubar WAI-ARIA design pattern](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/).

### Keyboard Support

| Key | Description |
| --- | --- |
| `ArrowDown` | Vertical orientation: move to the next trigger. Horizontal: enter the open panel. |
| `ArrowUp` | Vertical orientation: move to the previous trigger. |
| `ArrowRight` | Horizontal orientation: move to the next trigger. Inside content: move to the next link. |
| `ArrowLeft` | Horizontal orientation: move to the previous trigger. Inside content: move to the previous link. |
| `Home` | Move to the first trigger, or the first link when focus is in content. |
| `End` | Move to the last trigger, or the last link when focus is in content. |
| `Escape` | Dismiss the open panel. |

## API Reference

### NavigationMenu

Root element. Manages the active item, orientation, and mount behavior.

| Prop | Type | Default |
| --- | --- | --- |
| `value` | `string` | - |
| `defaultValue` | `string` | - |
| `onValueChange` | `(details: NavigationMenuValueChangeDetails) => void` | - |
| `orientation` | `"horizontal" \| "vertical"` | `"horizontal"` |
| `openDelay` | `number` | `200` |
| `closeDelay` | `number` | `300` |
| `disableClickTrigger` | `boolean` | `false` |
| `disableHoverTrigger` | `boolean` | `false` |
| `disablePointerLeaveClose` | `boolean` | `false` |
| `lazyMount` | `boolean` | `true` |
| `unmountOnExit` | `boolean` | `true` |
| `hideMode` | `"display-none" \| "activity"` | `"display-none"` |
| `id` | `string` | - |
| `ids` | `Partial<{ root, list, item, trigger, content, viewport }>` | - |
| `translations` | `IntlTranslations` | - |
| `asChild` | `boolean` | `false` |
| `className` | `string` | - |

Shark defaults `lazyMount` and `unmountOnExit` to `true`. Ark defaults them to `false`. Override both to `false` when using a shared viewport.

### Hooks and types

`useNavigationMenu` creates the state used by `NavigationMenuRootProvider`. `useNavigationMenuContext` reads the surrounding root.

| Property | Type |
| --- | --- |
| `value` | `string \| null` |
| `setValue` | `(value: string) => void` |
| `open` | `boolean` |
| `orientation` | `"horizontal" \| "vertical"` |
| `isViewportRendered` | `boolean` |
| `getViewportNode` | `() => HTMLElement \| null` |
| `reposition` | `VoidFunction` |

The module exports `UseNavigationMenuProps`, `UseNavigationMenuReturn`, `UseNavigationMenuContext`, `NavigationMenuValueChangeDetails`, and props types for the named parts. The root props type is `NavigationMenuProps`.

All DOM parts accept their Ark props, refs, `className`, and `asChild`. Each has a matching `data-slot="navigation-menu-*"` attribute; both roots use `data-slot="navigation-menu"`.
